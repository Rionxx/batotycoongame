# フェーズ3: コアロジック実装

## 目的

このゲームの「面白さ」を決める部分。UIなしで完結してテスト可能なロジックとして先に作ることで、
バグの原因切り分けを容易にし、UIフェーズでの手戻りを防ぐ。

## 前提条件

`docs/state-design.md` と型定義(`src/types/game.ts`)が承認済みであること。

## 進め方

1. `main` から `phase/3-core-logic` ブランチを作成する
2. 以下のモジュール単位で実装し、**モジュールごとにコミット**する(全部まとめて1コミットにしない)
   - `src/logic/tick.ts` — 経過時間から資源加算量を計算する純粋関数(オフライン復帰時の計算も含む)
   - `src/logic/upgrade.ts` — 施設レベルからアップグレードコスト・効果を計算する純粋関数
   - `src/logic/pigCollection.ts` — 豚の収集条件判定ロジック
   - `src/logic/constants.ts` — 成長率・基本値などのマジックナンバーを集約
3. 各モジュールに対応するVitestのユニットテストを **同じコミットで** 追加する(ロジックとテストを分けてコミットしない)
4. ストア(`src/store/gameStore.ts`)のアクションから、これらの純粋関数を呼び出す形に接続する
5. 全テストが通ることを確認してからプッシュする

## 実装方針

- **純粋関数として書く**: 引数を受け取り値を返すだけで、副作用(状態への直接書き込み)を持たせない。テストのしやすさと将来のロジック差し替えやすさのため
  ```typescript
  // 良い例
  function calculateUpgradeCost(baseCost: number, level: number, growthRate: number): number {
    return Math.floor(baseCost * Math.pow(growthRate, level));
  }
  ```
- **オフライン進行の扱いに注意**: `requestAnimationFrame` はタブが非アクティブだと間引かれる。
  `lastTick` のタイムスタンプと現在時刻の差分から資源加算量を計算する方式にし、
  タイマーの発火回数に依存しない設計にする
- **数値オーバーフローへの配慮**: 長時間放置で数値が極端に大きくなるケースを想定し、
  `Number.MAX_SAFE_INTEGER` 近辺の挙動をテストで確認する(フェーズ5でも再確認する)

## 完了条件(Definition of Done)

- [ ] tick処理・アップグレードコスト計算・豚収集判定がすべて実装されている
- [ ] 各ロジックに対応するユニットテストがあり、全て通過している
- [ ] マジックナンバーが `constants.ts` に集約されている
- [ ] ストアのアクションからロジック関数が呼び出される形で接続されている
- [ ] `any` 型を使っていない

## 次フェーズへの引き継ぎ

`phase-4-ui-implementation` はこのフェーズで実装したロジックをストア経由で呼び出す
UIコンポーネントを作る。UIフェーズではロジックの変更を行わない方針とし、
ロジックに不足があればこのフェーズに戻って修正する。承認時にその旨をユーザーに伝えること。
