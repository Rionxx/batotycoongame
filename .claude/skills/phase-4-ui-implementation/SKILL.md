# フェーズ4: UI実装(2D)

## 目的

フェーズ3までに固めたロジックと状態を、実際に触って遊べる画面にする。
このフェーズでは**ロジックの変更は行わない**(不足が見つかった場合はフェーズ3に戻る)。

## 前提条件

`src/logic/` のコアロジックとテストが承認済みであること。

## 進め方

1. `main` から `phase/4-ui-implementation` ブランチを作成する
2. コンポーネントを機能単位で分割し、**コンポーネントごとにコミット**する
   - `src/components/ResourceDisplay.tsx` — 現在のコイン数・毎秒増加量の表示
   - `src/components/BuildingList.tsx` — 施設一覧とアップグレードボタン
   - `src/components/PigCollection.tsx` — 収集済みの豚の一覧表示
   - `src/App.tsx` — 上記を組み合わせたレイアウト
3. コンポーネントはストアの状態を読み取り、ストアのアクションを呼び出すだけに留める(計算処理を書かない)
4. スタイリングは既存プロジェクト(罵倒デッキ構築ゲーム)と大きく乖離しない範囲で自由に選んでよいが、
   ユーザーに希望があれば確認する
5. 手動での動作確認手順を `docs/manual-test-checklist.md` に記録する

## 実装方針

- **ロジック層への依存は一方向**: コンポーネント → ストア → ロジック関数、の順で呼び出す。
  逆方向(ロジック関数がReactの状態やコンポーネントを参照する)は禁止
- **将来の3D化を意識した分離**: 資源やコレクションの「表示に使うデータ」はロジック層から
  取得し、描画方法(DOM/Canvas/WebGL)に依存しない形にしておく。今回はDOM(2D)で実装するが、
  この分離を守ることで将来React Three Fiberへの差し替えが「見た目の差し替え」で済むようにする
- **不要な再レンダリングを避ける**: Zustandのセレクタを使い、コンポーネントが必要な状態のみを
  購読する

## 完了条件(Definition of Done)

- [ ] `npm run build` がエラーなく通る
- [ ] 資源表示・施設強化・豚収集が画面上で一通り操作できる
- [ ] コンポーネントに計算ロジックが混入していない(ストア/ロジック層への委譲を確認する)
- [ ] `docs/manual-test-checklist.md` に手動確認手順が記載されている

## 次フェーズへの引き継ぎ

`phase-5-testing-balance` はこのフェーズで完成した画面を使って実際にプレイし、
数値バランスを調整する。UI実装フェーズの承認時に「触ってみてバランスに違和感がないか」も
併せて確認してもらうとフェーズ5がスムーズになる。
